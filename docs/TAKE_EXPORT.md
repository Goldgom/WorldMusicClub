# Practice take export

Export take data downloads the current in-memory practice session. Reset or score/setup replacement clears it. The outer format remains version 1: pass timelines, onset `inputs`/`captures`, event IDs, clock segments, assessment revisions, grace deadlines, interruptions and assessments keep their existing meanings. Only those onset inputs go to Rust `/api/assess`.

An optional `input_evidence` object has its own `version: 1`. It records musical input observed from the first capture-enabled practice pass until reset, including unscored input during pauses or outside onset windows. An assessment requested without playing does not enable this journal. Older exports without it have unavailable release evidence, not zero releases.

## Observations, not duration feedback

- `events` remains in callback/receipt order. Each observation has its own `event_id`, separate from legacy onset IDs. Events are never sorted, paired, or rewritten when a delayed callback arrives.
- `note_on` and `note_off` retain normalized `event_wall_ms`, callback `received_wall_ms`, finite original `raw_timestamp_ms` when available, and `timestamp_basis`. The latter distinguishes monotonic/epoch event times, clamping, receipt fallback, and application-clock cleanup. Normalized event, received and boundary times use the page's monotonic clock; `raw_timestamp_ms` may instead retain the browser's original epoch value. The session's manual onset latency offset is not applied to this raw journal.
- `onset_capture` references `{pass_id, event_id}` in existing pass captures, or `{pass_id: null, event_id}` in `unassigned_captures` for a recorded loop gap. Null means that observation was not retained as an assessed onset. Offs and cleanup never become assessed inputs or change assessment revisions.
- Explicit offs retain their encoding: MIDI NoteOff (including positive release velocity), velocity-zero MIDI NoteOn, pointerup, or keyup. `velocity` on an off is the received release value, not an attack. UI keyup/pointerup have null pitch because those events do not intrinsically encode a MIDI pitch; the source alias remains available for future correlation. Typing in text fields or dialogs is not recorded as musical input; a pending musical key release can still be retained after focus moves.
- `boundary` and `synthetic_release` record application cleanup, with reasons such as pause, loop boundary/stall, completion, focusout, blur, hidden/pagehide, pointer cancellation/lost capture, MIDI disconnection/replacement and CC120/123. These are not observed physical releases. Source-scoped boundaries identify a source alias; MIDI port/channel cleanup identifies its connection generation and optional channel; null scope identifies the session. `boundary_wall_ms`, when present, distinguishes the logical transport boundary from later cleanup observation time. Opening panels or browsing an idle, already-paused session creates no extra boundary. Actual lifecycle/port/loop events remain visible even without active contacts because callbacks can arrive late. Cleanup does not invent a missing note-off.

`source_id` is an opaque alias within this recorder. MIDI `source_generation` changes when a binding is replaced or reconnected; it is also recorder-local. Aliases preserve source distinctions for future analysis without exporting browser MIDI IDs, names, manufacturers, keyboard codes or pointer IDs. The journal also supplies input kind, channel where meaningful, and pitch. Repeated same-source attacks remain separate events; their release ownership is unknown.

The first implementation explicitly reports `pairing: not_implemented`, `release_assessment: not_implemented`, and `duration_eligibility: unknown`. Pedals and other controllers are not captured or applied; only CC120/123 application cleanup is observed. Key release does not establish audible sound end. No duration, sustain, fingering, guitar string, or independent piano voice judgement follows from these observations. Existing onset results and UI claims remain unchanged.

## Bounded retention

The journal retains at most 100,000 observations per session, and source/generation maps grow only for retained observations. At the first omission, a visible warning explains that release evidence reached its export limit while onset recording/scoring continues. Existing journal entries are not evicted. `truncated`, `omitted_observations`, and `first_omitted_received_wall_ms` disclose subsequent omissions; exports taken before that point remain immutable snapshots. Even an untruncated journal is not a guarantee of complete browser/hardware delivery or duration eligibility.

Validation distinguishes pure recorder/MIDI callback and Node DOM tests from hosted simulated-input browser checks. Physical MIDI hardware, device permissions, acoustic sustain and audio latency require separate validation.
