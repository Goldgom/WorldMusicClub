# WorldMusicHub 0.2.0-alpha.1

This alpha expands the first practice room into a small source-preserving repertoire and review workflow. It is still a portable Rust local server with a browser interface. The next regular Windows package checkpoint is the 100th meaningful development-branch commit; use the exact successful native workflow and `BUILD-INFO.json` to identify an accepted artifact. This feature guide is not itself a binary verification or a code-signing certificate.

## Changes since the first alpha

- Supported scores open in the bundled offline staff renderer by default. The explicitly named simplified pitch guide and Jianpu view remain available. Unsupported engraving reports its reason instead of hiding a missing staff.
- Opt-in measure following uses Rust's source-measure/repeat occurrences and source-note IDs. It changes pages only at boundaries, keeps the audio clock intact, labels repeat passes and suspends after manual navigation. It is not a per-note engraved cursor or a notation editor.
- The catalog starts from metadata and loads only the selected score; a bounded session cache avoids repeatedly transferring large retained-source archives. Copies stay independent of edits, and superseded requests cannot replace a newer local/library selection.
- The catalog adds the complete CC0 OpenScore edition of Schubert's *Wandrers Nachtlied*, D.768, alongside three original exercises and two public-domain practice excerpts. All 14 measures, 324 pitched written segments and 10 rests are retained; ties form 321 playback events. The original MSCX, raw converter XML, compatible XML copy, reference MIDI, license and hashes remain archived.
- This full edition is **written-note practice**, not an equivalent expressive performance. Its two turn signs produce six additional attacks in the converter MIDI, and two fermatas change reference timing. The app's canonical playback does not realize all ornaments, fermatas, dynamics, articulation, lyrics or engraving details. The source warnings remain visible and survive saving/reloading.
- A metronome can follow the shared playback clock. Choose notated-unit, quarter-note or dotted-quarter-note pulses explicitly; compound meters are not guessed. Excessively dense clicks or scheduling stalls stop the click track with a reason. The existing four-quarter count-in is silent.
- An explicitly confirmed whole-score/whole-part octave copy can help fit an instrument. It preserves the complete original and can be restored exactly while unchanged. It does not fold individual notes, remove inconvenient pitches or claim to solve arbitrary arrangements.
- A fixed source directory points to OpenScore, Mutopia and IMSLP with edition/rights/import guidance. It is a small set of starting points, not a comprehensive search service or automatic license clearance.
- Separately produced Audiveris 5.11.0 XML/MXL can enter an unplayable review draft with an optional original PNG/JPEG. The review UI supports exact note/rest timing, voices/staves/ties and explicit tempo/key corrections, with a complete-score JSON fallback. Fresh confirmation is required after edits; raw engine output and review history stay in the source archive. No OMR engine is bundled or launched by this bridge.
- Retained source files can be inspected and explicitly downloaded one at a time. Original editions, raw converter output, compatible copies, reference MIDI and license text have separate labels; checksum mismatch/unknown states remain visible. Closing or changing the score cancels stale inspection results. Full canonical JSON or a library backup remains the complete archive.
- Source import observations and producer/schema metadata now persist. Derived millisecond values survive JSON reposts without losing floating-point bits; canonical beat timing stays rational. Physical targets remain strictly linked to the source attacks.
- MIDI device removal/replacement releases only that port's held notes, preserving keyboard and other device input. This is covered by simulated input tests, not physical hardware certification.

## Try the complete piece

1. Open the Schubert edition and read its source/limitations summary.
2. Listen or inspect either staff page. The default 61-key range cannot play its low piano notes unchanged.
3. Select the voice part for a narrower exercise, or explicitly choose an adequate keyboard range. A 76-key preset fits the documented pitch range; this is not a claim about hand reach or fingerings.
4. Change speed or choose a linear A–B passage, then enable measure following if useful. Existing repeat scores require an unambiguous occurrence selection before written-beat loops can be offered.
5. Enter Practice only after compatibility checks pass. Onset scoring evaluates pitch/time; note releases, pedals, independent tied/unison voice durations and expression remain ungraded.
6. Save a separate local copy and export canonical JSON or a library backup. These preserve the full source archive, not just the displayed page or selected practice part. MusicXML/Jianpu exports alone do not preserve the complete archive.

## Import and storage compatibility

The musical format remains canonical version1. New optional producer metadata declares schema revision2, and retained import warnings add metadata that earlier strict readers may not understand. Newer builds accept older valid scores without inventing their producer history. Older alpha builds may reject newer metadata; keep originals and use a compatible app rather than stripping fields to force an import. See [format compatibility](../FORMAT_COMPATIBILITY.md).

Saved copies stay in the current browser/profile/origin. Changing the local port, browser or profile changes the visible library. Back up before moving environments or clearing browser data. A backup may include private source images/files and separately licensed music; sharing it also shares those retained contents.

## Remaining boundaries

- The built-in image aid is limited to a clean horizontal printed treble-staff crop and requires manual pitch/rhythm correction. General PDF, arbitrary printed pages and handwriting are not automatically supported. External OMR is optional, separately installed and reviewed; no calibrated confidence or universal recognition accuracy is claimed.
- Generic MXL import retains its selected score XML, not every ancillary archive file. Keep the original MXL separately. The external OMR review bridge explicitly retains its complete supplied MXL.
- MusicXML/MXL supports a bounded subset. Generic imports still reject DTD/entity declarations; the curated-compatible copy and narrowly recognized engine output record any permitted normalization separately. Unsupported semantics are not silently removed to make a score playable.
- Three reviewed candidates remain held: Brahms's *Wiegenlied* and Schubert D547 contain unsupported grace-note semantics; Clara Schumann's selected conversion has conflicting playback tempos. None is silently bundled as an accepted score.
- Keyboard and guitar arrangements have different ranges/polyphony. Guitar positions are pitch candidates, not verified ergonomic fingerings. Switching an instrument never authorizes dropping/transposing notes automatically.
- Live MIDI uses the browser's explicit permission flow. MIDI notation is inferred; unsupported controller/pedal/bend/tuning behavior remains limited. Device/audio latency, physical hardware, subjective sound and screen-reader behavior need real-device acceptance.
- Preview sound is approximate with bounded polyphony. No commercial recording, proprietary sound bank or unlicensed requested rhythm-game score is included. The requested-song cards remain metadata/official links for authorized local imports.
- Windows builds are unsigned and use browser rendering. Do not bypass system/browser security warnings blindly. Functional regression tests and file hashes are not independent security certification; adversarial-resource review remains incomplete.

## Release evidence

Continuous verification runs Rust tests on Linux/Windows, ordinary API checks, storage/schema/input unit tests, mocked UI flows, real Rust-backed browser workflows and offline engraving. The complete-edition case checks original-source equality, written/sounding counts, range gates, later pages and source-aware following. The raw reference-MIDI report separately exposes expressive timing/attack mismatches.

A native Windows milestone additionally builds the exact x64 MSVC executable, exercises its browser UI, packages licenses/catalog/schema/docs, inventories every file, verifies the ZIP, starts the extracted executable, compares its version/schema and embedded edition sources with the package, and verifies the renderer digest. `BUILD-INFO.json` distinguishes actual source count/SHA from any recovery milestone. A skipped gate, another commit's green tests or a Linux build is insufficient to accept a Windows artifact.

Development continues after this checkpoint. Broader reviewed OMR, additional lawful repertoire, richer notation semantics, arrangement assistance and physical MIDI/audio validation remain open work.
