# WorldMusicHub 0.1.0-alpha.1

The first portable practice-room alpha. The milestone is the 50th meaningful development-branch commit, including the repository's initial documentation commit. A source tag or a skipped workflow gate alone is not a verified Windows release: use the ZIP from a successful native Windows packaging run and inspect its `BUILD-INFO.json` and SHA-256 files.

## What is included

- Rust-owned canonical score v1 with exact rational written timing, note spelling, rests, voices/staves, tempo/key/meter maps, basic ties/repeats, retained original sources and provenance
- Three newly authored exercises and two manually encoded public-domain opening excerpts; all source/arrangement decisions documented
- Piano keyboard presets/custom ranges, guitar tuning/fret/capo candidates, falling-note practice, keyboard/pointer control, synthesized preview, part selection, A–B ranges and calibrated MIDI note-on capture
- Order-preserving timing/pitch matching, one physical piano attack for truly simultaneous same-key unisons, complete source-note mappings, retained/revisable practice takes and explicit interruption/boundary-review states
- Offline OpenSheetMusicDisplay staff preview alongside the basic pitch guide and numbered-note display; light/dark/system/custom themes and keyboard-accessible controls
- Local import of canonical JSON, bounded MusicXML/MXL, limited MIDI and the documented numbered-text dialect
- A small local printed-staff image recognizer with crop selection and mandatory manual pitch/rhythm review; a reviewed melody can be exported as numbered text when representable
- Explicit saved-score copies in the browser, revision-aware deletion/update protection and atomic, Rust-validated library backups
- Canonical JSON, bounded MusicXML and roundtrip-verified monophonic `.jianpu` export

## First practice session

1. Extract the entire Windows ZIP and read `START-HERE.md`; keep the notices folder with redistributed copies
2. Start `WorldMusicHub.exe`; it opens the local browser interface. Keep its console open
3. Pick an original exercise, choose the keyboard size/range and listen first
4. Switch to Practice only after the instrument compatibility check succeeds; use the mapped computer keys, pointer or explicitly connected Web MIDI device
5. Review timing/pitch feedback, try a slower passage, then export your take if useful
6. For your own score, import an authorized file. For a PNG/JPEG fragment, crop one clean horizontal treble staff and manually verify every note and duration before creating a practice score
7. Save explicitly to the local library and export a backup. Another browser/profile/port has a separate library; browser data removal or eviction can remove saved copies

## Boundaries that matter

- This is a portable Rust loopback server with a browser interface, not a native-widget desktop application. It does not require a cloud account or send scores to an OMR service
- General PDF, handwritten music and arbitrary score images are not recognized. The image aid does not determine rhythm, accidentals, key signatures, chords, voices or ties automatically; heuristic confidence is not calibrated correctness
- MusicXML imports preserve supported musical structure plus the exact source, not every engraving or performance instruction. Complex navigation, unsupported microtones/expression and compressed-file limits are reported rather than silently claimed as supported
- MIDI notation is inferred. Pitch bend, pedal semantics, percussion and ambiguous overlapping same-pitch events remain limited; live scoring measures note-on pitch/timing, not releases, sustain, fingerings, articulation or expression
- A single physical piano attack may represent multiple exact unison source events. Independent voice-release requirements remain ungraded. Guitar pitch candidates are not a validated fingering or proof of hand reach/sustain feasibility
- Timing windows and latency offsets are practice aids, not a certified instrument-performance assessment. Ambiguous adjacent-pass events are retained and marked for review; hardware/audio latency needs testing on the user's setup
- Staff engraving is an optional bounded static preview. It is not an interactive professional notation editor, synchronized engraving cursor or lossless interchange roundtrip
- Numbered-text export supports one non-overlapping lane and constant maps. Unsupported polyphony, written ties/repeats/pickups and unrepresentable alterations are refused; retain JSON/MusicXML for the full archive
- Synthesized timbre is approximate and preview polyphony is capped. No commercial recordings, sample banks or unlicensed song scores are bundled
- Requested commercial-song cards are metadata and official-source links requiring an authorized local score. Noncommercial use does not itself grant redistribution rights
- Early Windows builds are unsigned. Do not bypass operating-system/browser security warnings blindly. Functional regression coverage is not a security certification; independent adversarial-resource review remains incomplete

## Verification and continuation

The continuous checks cover Rust on Linux/Windows, ordinary local-server integration, frontend unit tests, mocked UI regressions, real Rust-backed app flows, and the actual offline renderer. Native Windows milestone packaging also starts the compiled executable, exercises the real browser UI, inventories licenses and every packaged file, verifies the ZIP, starts its extracted executable and checks the embedded renderer's checksum. The exact workflow must pass before that artifact is described as verified.

Not yet verified by these automated checks: real MIDI hardware, subjective audio/timing behavior, Windows screen-reader acceptance, code signing, universal score/OMR fidelity, or operation on every Windows/browser combination. Development continues after this alpha, with metronome/count-in audio, richer notation/editing, device diagnostics and additional reviewed score sources as useful next areas.
