# Recovery after the 100-commit Windows snapshot

The original commit-100 native Windows package completed its own build, API checks, browser workflows and extracted-package checks. A separate Windows verification job failed when two parallel asset-test fixtures chose the same temporary directory from their process ID and wall-clock timestamp. The original snapshot and artifact remain unchanged.

This recovery adds a process-local atomic sequence to the test fixtures. A deterministic regression creates two fixtures at one clock tick and checks that their files and cleanup remain independent. The correction is confined to test code; it does not relax asset collection or change application permissions.

The recovery also includes the meaningful development commits after100:

- Exact rational A–B boundary checks, including complete tied sustains
- Visible theme/settings recovery and contrasting keyboard focus
- Rust-derived per-pitch onset feedback with distinct missed/extra counts
- Complete inert MXL archive retention through source downloads and backups
- Size-aware canonical JSON downloads without removing score/source fields
- Additional exact MusicXML/Jianpu roundtrip checks and corrected archive guidance

These additions mean the recovery is its own build, not a claim of binary equivalence to100. Read the actual source SHA, commit count, `recovery_for` value, compiler versions, file inventory and ZIP checksum in its build evidence. Acceptance requires the exact recovery commit's full verification and native packaging jobs to pass; this source document does not certify an unbuilt candidate.

The interface still uses the browser-based practice-room layout. The requested immersive landscape game redesign is a subsequent development stage and is not included in this recovery. Image recognition remains limited and review-dependent; live physical MIDI/audio, expressive playback, release/pedal/fingering grading and independent security certification remain outside the verified scope.
