# Optional offline staff engraving

WorldMusicClub uses the open-source **OpenSheetMusicDisplay (OSMD) 2.1.3** renderer for its supported-score default staff view, with an explicit simplified pitch-guide fallback. OSMD uses VexFlow for professional staff layout. This is a presentation adapter: Rust remains authoritative for score validation, exact rational durations, repeat/tie timing, playback, input assessment and export. Jianpu remains the separate WorldMusicClub view. No OSMD paid player, transpose plugin, Jianpu plugin, audio service, remote score loader or hosted font is included.

An unbuilt checkout does **not** have the professional renderer available. Keep the clearly labelled basic pitch view usable when assets are absent, the score exceeds limits, or engraving fails. An OSMD preview is not a claim of lossless recovery of the uploaded notation: canonical exports infer rhythmic spelling/clefs and surface their own diagnostics.

## Build and distribution

The exact npm development dependency is `opensheetmusicdisplay: "2.1.3"`. Commit the npm lockfile. Build with:

```sh
npm ci --ignore-scripts --omit=optional
node scripts/prepare-engraving.mjs
node --test tests/engraving.test.js tests/engraving-assets.test.js
# After a Rust build and an available Playwright Chromium:
npm run test:engraving-browser
```

`--omit=optional` avoids the unused native GL dependency. OSMD itself must be a development dependency, not an optional dependency, for that command. The preparation script runs no downloads, installers, third-party code or lifecycle scripts. It checks the package version and the pre-reviewed bundle SHA-256 before copying. A changed package, unexpected license/dependency, missing notice, or changed bundle fails the build. Update the pin/hash only after a fresh API/security/license review.

## Frontend contract

```js
import {renderEngravedStaff, disposeEngravedStaff} from './engraving.js';

// exported is the complete Rust /api/export/musicxml response.
// A canonical part ID is NOT the same as the generated MusicXML P1/P2 identifier.
const selectedXmlId = selectedCanonicalPartId
  ? exported.part_id_map[selectedCanonicalPartId] : null;
const rendered = await renderEngravedStaff(container, exported.xml, {
  dark: false,
  fromMeasure: 1,
  toMeasure: Math.min(32, numberOfExportedMeasures),
  partIds: selectedXmlId ? [selectedXmlId] : null,
  zoom: 1,
  responsive: true,
  identity: {score, noteMap: exported.note_id_map,
    partIdMap: exported.part_id_map, voiceIdMap: exported.voice_id_map},
  onMappingChange: mapping => updateNotationNotices(mapping.diagnostics),
  onError: failure => showBasicViewWithReason(failure.message),
}, abortController.signal);
if (!rendered.ok && rendered.status !== 'cancelled') {
  showBasicViewWithReason(rendered.message);
}
// Membership and source-measure ordinal come from the checked Rust written cursor.
// This changes verified notehead fills, with no render, playback or scoring call.
rendered.setExpectedWrittenNotes({sourceNoteIds: ['canonical-note-id'], sourceMeasureIndex: 0});
rendered.clearExpectedWrittenNotes();
// Switching notation views, closing the score, replacing the container, or unmounting:
disposeEngravedStaff(container); // or rendered.dispose(); both are idempotent
```

Only an **XML string** is accepted. URL strings, Blobs, MXL archives and arbitrary remote assets are rejected. Internally the validated XML is parsed into a `Document` and passed to `osmd.load(document)`, deliberately bypassing OSMD's automatic URL interpretation of short strings. Imported source is never inserted as HTML.

The promise resolves with `{ok, status, message, metadata, dispose, resize, setExpectedWrittenNotes, clearExpectedWrittenNotes, mappingStatus}`:

- `ready`: an actual SVG exists in the container
- `unavailable`: missing/failed vendor asset, wrong runtime version, or no XML parser
- `unsupported`: unsupported resources/features or a deliberate safety limit
- `invalid`: malformed XML, invalid part selection/options, or an invalid range
- `error`: OSMD load/render failed or produced no SVG
- `cancelled`: abort or a newer render superseded the request; do not overwrite the new view with fallback

Successful metadata is `{noteCount, measureCount, partIds, fromMeasure, toMeasure}`. When extra original tie context is loaded, `modelFromMeasure` and `modelToMeasure` additionally identify that bounded model range; `fromMeasure`/`toMeasure` still identify only the requested displayed measures. `partIds` lists the XML IDs present in the input. `resize()` rerenders only when width changes, returning false after disposal or an error. `onError` is optional and is called on a later resize failure so the UI can restore its basic view. Initial failures are returned normally.

### Parts, pages, responsiveness and playback

- `partIds` is `null`/omitted for all parts, or a nonempty unique list of **MusicXML** IDs. With a complete verified Rust identity map, only selected parts are copied into the renderer view; the downloadable XML and Rust scoring data are unchanged. Small inputs without a valid map keep the original static-engraving path with OSMD `Instrument.Visible` and the 2,000-note full-input limit
- `fromMeasure`/`toMeasure` are inclusive **one-based source ordinals**, counting an initial pickup. They are not printed MusicXML measure labels or quarter-note beats. The pinned adapter resets OSMD's pickup-number correction and sets local view indexes explicitly. A separate table maps every local measure back to its original source ordinal
- Automatic multi-measure-rest generation is disabled with OSMD's supported `autoGenerateMultipleRestMeasuresFromRestMeasures` option. Its default considers only visible staves and collapses consecutive rest measures into the first one, leaving no graphical measures when a later source window contains only those continuations. Beethoven's voice-only measures 17–18 exposed this after viewing the full score. Keeping separate rest measures preserves source-ordinal paging without changing the canonical score or exported XML
- Omitted range defaults to the first 32 measures, or 32 starting at `fromMeasure`. No request is silently clamped: explicitly exceeding the score or requesting over 64 measures returns a reason
- This is an endless-height, width-responsive engraving of a measure window, not print-paper pagination. The caller owns Previous/Next controls and their labels. Never reuse basic-view beat windows as measure indexes
- `zoom` is 0.5–2. Container width is bounded to 320–4096 px. Optional `width` fixes that width and disables automatic observation. Narrower viewports should permit horizontal scrolling
- `autoResize` and OSMD cursor/following are disabled. A single adapter-owned `ResizeObserver` coalesces width changes. It and pending animation frames are disconnected on replacement/disposal; no global resize listener is registered
- Render calls supersede earlier calls for the same container. The adapter checks generation/cancellation after asynchronous work and never lets late loads overwrite a newer view. The caller must also guard its own earlier asynchronous Rust export requests before calling this adapter
- The adapter does not use OSMD playback or cursor timing. It marks only the expected written identities supplied by the checked Rust cursor, separately from pressed keys and assessed hits. The application can explicitly follow Rust source-measure/repeat occurrences by changing the window at page boundaries; manual navigation suspends following. This does not reschedule audio or render on each animation frame. With Follow measures enabled, the view also reveals verified expected glyphs within the notation pane, including later systems on the same page

In the short-landscape side-by-side layout, paging and Follow controls wrap normally above a dedicated full-width, non-shrinking status row. A zero-basis flexible status paragraph can otherwise occupy only the remaining sliver beside these controls under different system-font metrics: Windows review exposed this at 844×390, pushing all 16 rendered noteheads below the dock. The status remains in normal flow with unbounded wrapping and pane scrolling; no controls, status text or notation diagnostics are clipped or removed to gain space. The Node CSS/DOM regression protects this layout contract, while actual notehead visibility must still pass exact-source hosted and Windows browser geometry checks.

## Exact written-note binding

The optional `identity` object supplies the canonical score and complete version1 Rust note/part/voice maps. The helper verifies every canonical note/rest is fully covered by non-overlapping written segments, then independently walks generated XML divisions, forward/backup cursors, chords and ties. It checks exact note IDs, measure ordinals, staff/voice/lane, written pitch, rational onset/duration and effective ties. Missing, incomplete, oversized or unknown-version identity metadata disables highlighting with an explicit diagnostic while retaining ordinary static engraving only within the original 2,000-note full-input limit. Larger inputs require the complete map before any page can enter OSMD. Source validation has a separate maximum of 8,192 notes/segments and 4 MiB of serialized map data; the unchanged XML element/byte limits apply first.

OSMD does not expose the generated XML note ID on its `Note`. Model matching therefore requires a one-to-one tuple on both sides: generated part, original source ordinal resolved from the local identity index in public `Sheet.SourceMeasures`, staff identity within the instrument, numeric XML voice, measure-relative onset, note length and exact source pitch/rest. WholeValue is included in OSMD fractions and whole-note units are converted to quarter beats exactly. Source pitches use OSMD's XML-octave offset. Floating tolerance, nearest pitch and note/SVG ordering cannot select a source identity. Fraction rounding by OSMD produces an unavailable mapping, never a changed Rust time.

A model match is still not proof of an individual glyph. The pinned renderer's `GNote(note)`, `sourceNote`, `vfnoteIndex`, VexFlow chord key/head counts, stored group ownership and current mounted SVG must agree. `getNoteheadSVGs()` returns the entire chord, and `GraphicalNote.setColor()` colors that whole set; neither is used to guess one head. The guarded indexed-head relationship depends on this pinned bundle and its verified draw loop. Unsupported, hidden or transparent heads remain unchanged. Shared DOM heads and coincident same-staff/onset glyphs are marked unavailable with their complete canonical/XML source sets, including cases with different accidentals.

`setExpectedWrittenNotes({sourceNoteIds, sourceMeasureIndex})` accepts an explicit array of exact unique canonical strings and one zero-based source-measure ordinal. Unknown/duplicate IDs, invalid measures or membership outside that measure are rejected and clear prior highlighting. Empty membership clears the mark. Only verified head-path fill attributes change; stems, beams, ties, accidentals, input state and canonical/OSMD source-note objects remain untouched. Clearing or disposal restores the exact original attribute presence/value. Separate rectangular outline markers provide a non-color cue outside the unchanged musical SVG. They preserve hollow noteheads and rests, are pointer-inert and hidden from assistive technology, and are created only when bindings rebuild. Clearing hides all markers; disposal removes the owned layer. The staff image refers to the existing quiet expected-note text, separately from raw input and assessed hits. No transitions, audio changes or hit judgment are introduced.

`mappingStatus()` and `onMappingChange` expose `ready`, `partial`, `unavailable` or `not-requested`, version1, complete/displayed segment counts, distinct verified glyph count, per-segment binding status and diagnostics. A `not-displayed` segment belongs to another part or source page; it is distinct from a missing/ambiguous glyph. Counts describe the current rendered window, which may extend below the notation scroller. Binding diagnostics share the existing notation notices rather than adding a persistent status row.

Every initial render or resize creates fresh bindings. Accepted expected membership is replayed after resize; the view forwards current membership after theme/part/page rendering. Replacement, cancellation and disposal invalidate old handles and restore their owned paint. Per-note updates diff the verified set and never invoke rendering or search the SVG tree. `expectedNoteBounds()` samples fresh rectangles only from the currently selected, verified mounted heads; missing/shared/hidden heads, replaced paths and reparented glyphs never become a guessed scroll target. A newer Rust occurrence must agree with the selected source measure before it can reveal a head. `renderGeneration()` changes on binding rebuild. With Follow measures explicitly enabled, the view checks geometry only after source identity, occurrence or render/viewport geometry changes (including dock/detail resizing and re-enabling Follow), and scrolls `#notation-dock` vertically and `.engraving-scroll` horizontally by the minimum clamped amount. Movement is instant, including under reduced motion, and never moves the body, stage, focus or playback clock. A simultaneous group that fits the viewport keeps all verified heads visible, shrinking its contextual margin when needed. An oversized group reveals its topmost verified head and reports partial visibility. Optional geometry failures leave playback and the pane unchanged. Wheel, touch movement, scroll keys and direct staff/scrollbar interaction suspend following until the user enables it again. Manual mode does not reposition the pane.

## Safety and bounded support

Preflight checks the entire document, including hidden parts and measures outside the displayed window. Limits remain 8 MiB UTF-8 XML, 50,000 XML elements, nesting depth 32, 16 parts, 512 measures per part and 64 displayed measures per call. Complete canonical source validation permits at most 8,192 note/rest segments under those unchanged XML limits and a 4 MiB identity-map limit. Each actual renderer view is limited to 2,000 note/rest elements, including generated invisible timing rests. The parsed OSMD model is checked against the same 2,000-note limit before graphical layout. Text/attributes and numerical layout inputs are also bounded. Up to 8 staves per part, divisions up to 1,000,000, and ordinary tuplet ratios up to 128 are accepted. A narrow canonical extension accepts reduced actual:normal components up to 2,048 on one shared divisions grid up to 2,048: both components, note duration, plain note type and normal type must agree exactly; actual must be greater than normal and less than twice normal. Dots, explicit tuplet notation, unsupported types and mixed grids do not take this extension. The paired validation runs on the entire source, including off-page/hidden parts. More unusual exact exports can still be downloaded but may require the basic view. Tuplet/resource-limit rejection must be shown explicitly.

DTD/entity declarations, processing instructions other than the XML declaration, active attributes, links/images/foreign namespaces and unrecognized elements are rejected. Ordinary score-partwise notes, rests, chords, multiple voices/staves, ties, clefs, key/time signatures and standard directions go through the real OSMD engine; no pitch-only drawing is presented as staff engraving. The pinned OSMD reader applies `parseInt` to `<voice>` values. The adapter rejects non-positive-integer voice IDs explicitly rather than allowing string labels to merge; the Rust exporter supplies deterministic integer lane IDs and `voice_id_map` metadata while preserving canonical voice labels. Preflight is a safety/shape gate, not a second score validator. Always obtain this XML from the canonical Rust exporter and show its diagnostics.

OSMD's layout is synchronous once called, so abort cannot interrupt a render already executing on the JS main thread. Caps bound input complexity but are not a time/memory guarantee. Selecting a page never bypasses full-source validation. A page exceeding the renderer budget is rejected explicitly; choose fewer measures or one part. The request is never shortened, rounded or partially rendered to fit.

### Exact source-bound excerpt rhythms and incoming page ties

The source-bound Rust excerpt exporter keeps the existing 2,048 ratio and grid limits by splitting an otherwise oversized nonstandard interval into adjacent exact pieces on its original integer tick grid. For example, a duration of 4,095/1,024 quarter beats becomes 2 + 2,047/1,024. Pitched pieces have ordinary adjacent ties; rest pieces have no ties. Every piece has a unique XML ID and the same original source-note ID. The canonical note, complete duration, source events, playback and targets are unchanged. Ordinary full-score MusicXML export retains its original spelling. Segment, XML, map and renderer budgets still apply to every added piece, and larger unsupported grids are not disguised or rounded.

OSMD 2.1.3 drops a tie chain whose first loaded note is an incoming page continuation carrying both stop and start. For a page admitted against the complete native source, the adapter can restore that within-page chain through the pinned renderer's public `Tie` constructor and `AddNote` method. Admission requires the privately retained boundary evidence, one unchanged source ID, unique existing model notes, matching pitch/part/staff/voice/lane, exact adjacency and complete clipped duration, and no existing NoteTie anywhere in that chain. It adds no note, seed, outside context, or duration, and changes no source XML flags. The original strict model tie-membership guard then runs normally. Wrong or partial existing ties, generic scores, copied or invented boundary objects, cross-source joins and nonadjacent chains remain rejected. Page-edge continuation metadata remains explicit; this does not claim to draw a missing outside note or a half-curve at the page edge.

Original regressions are `tests/fixtures/exact-rhythm-excerpt.json` (generated by the Rust exporter test with isolated simultaneous C/D keys and a rest) and `tests/fixtures/basic-key-open-tie-page.json` (one authored ten-quarter C4 followed by two silent quarters, generated by `scripts/generate-open-tie-fixture.py` through the real native stdio driver). Node tests verify exact model clocks, source coverage, all internal tie members and negative admission. The hosted `native incoming continuation and bounded exact-rhythm pieces own real SVG tie curves` case additionally requires real graphical ties, mounted nonempty SVG curves, complete glyph identity and unchanged source data. It must pass hosted Chromium; Node success alone is not visual acceptance.

### Exact bounded presentation projection

After full source/XML/identity validation, `engraving-projection.js` clones the requested parts and measure window into a disposable Document. A displayed tied segment also requires its complete original tie chain: exact adjacent part/staff/written-pitch/onset/end identities locate that chain, preferring the same source note for split segments and then the original canonical voice, and surrounding original measures are retained as nondisplayed context. All original context notes, IDs, tie starts/stops, durations and pitches remain unchanged; no tie is seeded, shortened or stripped. The total loaded range, including this context, must remain within 64 measures and 2,000 notes including timing rests. An ambiguous chain or over-budget context causes an explicit fallback. This bounded resolver supports unambiguous same-staff cross-voice joins, including the bundled D768 edition. XML voice allocation cannot sever an authored tie. Both directions must identify the same adjacent pair; ambiguous joins are refused. Cross-staff or enharmonic joins supported by Rust still require the simplified pitch guide even when their entire chain fits; they are not reinterpreted or silently removed. Only the requested measure indices are drawn; context is never counted as a displayed segment or bound as a current-note glyph. The first retained measure inherits effective divisions, key, meter, staves, clefs and supported staff attributes from prior measures. Initial attributes in the selected measure override inherited state in one merged attributes element, preventing OSMD from retaining an obsolete clef. Original printed measure numbers, implicit pickup flags, ties and repeat marks remain in the selected measures. Interior attribute changes are refused explicitly: OSMD hoists some of these to the bar start, so this view falls back while the original export remains available. Source measure ordinals and original XML note IDs remain separate from OSMD’s rebased local clock. Successful public metadata and complete mapping counts still describe the original score; off-page/other-part bindings remain `not-displayed`.

OSMD 2.1.3 ignores canonical `<forward>` silence when determining some measure clocks. The projection replaces each forward gap with exact nonprinting rests and fills every short lane tail before its backup. Backups then span the complete canonical bar. Leading gaps look ahead to the lane’s explicit staff/voice. Empty bars use an unused presentation voice with the exact canonical duration. Padding has no source ID, never enters the Rust score/map/export, and cannot be matched or scored as a canonical note. Long gaps are split into pieces of at most one whole note; residual duration/divisions are retained exactly, with no added tuplet ratios or rhythmic quantization. An exact integer repartition avoids leaving a residual at or below the pinned converter’s 1e-4 whole-note floor; an isolated gap below that floor is refused. Unsupported grids/cursor programs fail explicitly. The pinned reader’s exact measure lengths and rebased timestamps are checked for the complete loaded context before graphical layout; a changed clock cannot be published as a successful staff view. Every displayed tie chain must also have the exact expected ordered `NoteTie.Notes` membership on the real reader model, with all members sharing that same tie object. Flags surviving in XML are insufficient: OSMD drops orphan stop+start continuations when their original start is absent. Missing, singleton, merged or otherwise changed model ties are rejected before graphical layout.

The clone is rechecked for byte, element and depth bounds, and all original plus generated notes count toward the 2,000-note view limit. The original downloaded MusicXML and canonical JSON remain byte-for-byte unchanged. This does not alter playback, assessment, written-cursor timing, repeat expansion or the source archive.

OSMD’s reader has one independent diagnostic limitation: for multi-instrument implicit pickup bars, it compares duration Fraction objects by reference in part of its warning condition. Equal exact pickup durations can therefore produce a “Given Notes don’t correspond to measure duration” warning on another instrument’s staff. The adapter preserves the original pickup and meter and verifies their exact clocks; it does not rewrite musical time to suppress that renderer warning.

The pinned reader also expands some short measure fractions to the active meter denominator without requiring an integral scale. Its `MusicSheetReader.checkFractionsForEquivalence` changes a 1/3 whole-note measure under 4/4 to `1.3333333333333333 / 4`; later timestamps can inherit that representation. Before the unchanged integer-only model guard, a narrowly source-bound repair checks every original and generated-rest pitch/onset/duration/voice/staff/visibility tuple against a private snapshot of the validated projection. Each instrument must end at the exact canonical measure length. It accepts only the exact raw result of the pinned expansion and its accumulated reader clock, then replaces disposable measure durations/timestamps with exact fractions derived from the independently verified source. It never approximates a floating value, edits note objects or pads a short bar to its meter. All checks precede writes; wrong pitches, hidden rests, nearby floats, missing notes, changed meters/source, and forged projections are refused. The real-reader and adapter regressions cover short bars inside and at the end of a page, selected parts and later-page origins; the original hosted SVG scene additionally requires exact source-owned visible glyphs and resize/current-note behavior.

Interior key changes remain unsupported for staff projection. In 2.1.3 `InstrumentReader.saveAbstractInstructionList` writes a key change to `FirstInstructionsStaffEntries`, while `MusicSheetCalculator.createGraphicalMeasure` processes only clefs among timed staff instructions. Reattaching a timed key object would therefore not prove a visible key at its source time. The original pinned-reader regression demonstrates the hoist and keeps the explicit fallback; the basic view, exact playback and untouched MusicXML export remain available. True support requires a separately verified timed-key engraving or a source-bound measure-fragment projection, including notes sustained across the key boundary.

The adapter requests only its bundled same-origin JS. It needs no remote `connect-src`, CDN, font URL or `unsafe-eval`. Current server policy (`script-src 'self'`, existing `style-src 'self' 'unsafe-inline'`) is sufficient. Keep `object-src 'none'` and `base-uri 'none'`. OSMD/VexFlow glyphs are inline paths; text uses local/system fonts. Do not add a URL-loading fallback on a bundle error.

## Verification and source references

`tests/engraving.test.js` uses small DOM/OSMD doubles to cover preflight caps, malicious resource inputs, part/range options, missing assets, retry/deduplication, cancellation, out-of-order resolution, responsive cleanup and renderer errors. These tests **do not verify actual glyph rendering or browser layout**. `tests/engraving-assets.test.js` verifies the real pinned npm bundle, checksums and generated notices without running it.

`tests/engraving-projection.test.js` uses original synthetic 2,280-note data and the real pinned OSMD reader to verify bounded later pages, selected parts, inherited state, leading/interior/tail silence, empty measures, pickup clocks, full-source validation, source IDs, tied segments across a page, repeated printed labels, and post-reader clock refusal. Original 12-measure sustain tests cover both context boundaries, mixed voices/parts, explicit ties between distinct canonical IDs and voices, exact canonical-voice priority and ambiguous-join refusal, context budgets, display-only matching, complete-context clocks, and a missing-NoteTie failure despite otherwise exact note identities. The adapter integration test verifies that a broken model tie is refused before any graphical layout. These are parser/model checks, not SVG/browser acceptance. The hosted browser suite adds an original 2,406-note Rust-exported fixture, observes the real renderer input, and checks actual glyph mapping/current-note updates, parts, pickup/later pages, ties/repeats and resize rebinding.

`tests/engraving-note-map.test.js` additionally checks exact segment/model cardinality, unequal-duration chord isolation, rests/splits, duplicate labels, Unicode identities, coincident/shared glyph refusal, invalid requests, exact attribute restoration and resize/disposal using explicit non-rendering doubles. Registered real-OSMD cases in `tests/engraving-browser.test.js` verify independent head geometry for displaced seconds and both stem directions, unequal durations, rests, voices/unisons, split/tied notes, exact thirds, page/part changes, light/dark resize, replacement and malformed metadata. They also require no redraw, graph-color call or DOM replacement during expected-note updates. Additional cases check outline/head geometry, fresh bounds after scrolling, and same-page reveal at 844×390 with manual suspension and byte-equivalent paused take data. Every new geometry assertion requires its exact-source hosted run; local Node and HTTP checks do not establish it.

Real browser CI must prepare the vendor assets, render the Rust-exported original fixtures, assert SVG staff paths/measure content, exercise multi-voice/two-staff/tie/key/time cases, initial pickups and paging, change themes/width, and verify that network requests stay local. Local browser execution was blocked in the implementation environment and was not retried through an alternate route. Hosted real-browser acceptance later passed on the exact [commit91 workflow](https://github.com/Goldgom/WorldMusicHub/actions/runs/36811215258), including complete D768 multi-staff SVG, both pages, light/dark display, range gates and source-aware following. These hosted checks are distinct from local browser execution or physical MIDI/audio acceptance.
