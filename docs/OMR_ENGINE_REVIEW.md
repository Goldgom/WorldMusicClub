# Optional local printed-score OMR: evaluation and integration boundary

Status: evaluation in progress, not bundled and not an automatic general-purpose import feature. The existing lightweight image aid remains usable without this dependency.

## Pinned engine evidence

Audiveris 5.11.0 was released on 2026-07-11. Its [official release](https://github.com/Audiveris/audiveris/releases/tag/5.11.0) supplies native installers with a Java runtime. Its [license is AGPLv3](https://github.com/Audiveris/audiveris/blob/5.11.0/LICENSE); WorldMusicHub does not silently redistribute it under the app's MIT license. Installing, bundling, modifying or operating it is a separate licensing/deployment decision. A successful recognition does not establish rights to the input score.

The project-local evaluation uses the official Ubuntu 24.04 x64 package (77,716,868 bytes), verified against release SHA-256 `f20113aaa33b3149ec8d6a09b2a7963360e65fafd92d69389987a85bbc3ec7a3`. It was extracted to a private task directory without system installation. The reported runtime is Audiveris commit `9e1e55cd2746037d059345881c53e6a6754bffbd`, OpenJDK 25.0.3 and Tesseract 5.5.2. Private launcher configuration limits the Java heap to 1 GiB and selects headless/private-home operation; all XDG directories must also be explicitly private. No global configuration is changed.

The [pinned installation guide](https://github.com/Audiveris/audiveris/blob/5.11.0/docs/_pages/tutorials/install/binaries.md) documents a Windows license checkbox and publisher/installation prompts. WorldMusicHub must not silently accept these or bypass system warnings. User-machine installation is optional and user-controlled.

## Actual first result and better fixtures

The first batch attempt used the original, unmodified 1440×1100 staff-rendering test image. Audiveris stopped after about two seconds because its staff-line spacing was only 10 pixels; it reported insufficient resolution and produced no MusicXML. That is a failed recognition, not a completed conversion. The evaluation also found that an OCR language model needs provisioning in the private engine data directory.

Fresh high-DPI original melody and multi-staff duet renderings are generated by the actual Rust/OSMD browser test. Each PNG has a SHA-256-linked ground-truth JSON containing the canonical score and generated MusicXML. They remain within the app's 16-million-pixel cap. Generating these fixtures is not evidence that Audiveris recognized them correctly; the separate engine result must be compared note-by-note and rhythm-by-rhythm. No commercial score or scanned edition is used for this benchmark.

## Adapter contract before user-facing automation

The [official CLI](https://github.com/Audiveris/audiveris/blob/5.11.0/docs/_pages/guides/advanced/cli.md) supports batch transcription, MusicXML export, explicit output folders and an option delimiter. It also supports argument files and running Java classes, which are inappropriate for an image-import API.

An integration must therefore:

- Use an explicitly trusted, separately installed engine and a fixed argument list; never take executable paths, arbitrary constants, argument files, class names or shell fragments from imported content or HTTP requests
- Stage a bounded image under a generated private filename, with no source filename used as an option; use ordinary MusicXML/MXL as the interchange boundary
- Keep every config/cache/temp/output path inside its job/profile area, limit runtime and logs/output, cancel the entire owned job, and handle failure without activating a score
- Retain the original image, engine version/options and unmodified recognized MusicXML with the reviewed canonical result
- Mark all recognized output as unreviewed; missing confidence is unknown, not a fabricated high score. Permit correction of voices, chords, pitches, rhythms and ties before practice
- Require a fresh explicit review confirmation after edits or replacement; preserve all source notes and show unsupported-import diagnostics
- Continue local base-app functionality when the engine is absent. Do not upload source images to a cloud OMR service by default

The current evaluation runner uses a 120-second deadline, 1 MiB log cap, 128 output-file cap and 64 MiB output-byte cap. Java heap limits do not fully bound native allocations; production process isolation/cancellation and compatibility still require verification. Original input/output stays outside published application assets. Mature OMR is still imperfect and is not a promise of arbitrary image/PDF/handwriting fidelity.

## Measured high-DPI result (2026-09-30 UTC)

The next runs used genuine 3× OSMD rendering, 36-pixel staff spacing, and the original melody/duet ground truth from [verified commit60 CI](https://github.com/Goldgom/WorldMusicHub/actions/runs/36792679835). They did not enlarge the rejected low-resolution screenshot. The [machine-readable report](evaluations/audiveris-5.11.0-original-fixtures.json) retains engine/model/input/output hashes and separate written-note, sounding-note, rhythm, meter, key and tempo results.

- Melody, 3594×1314: the 15 pitched written events plus one rest matched spelling, onset, duration, voice/staff and tie state exactly. All sounding pitch counts matched. The printed quarter=90 was missed; imported playback defaulted to120 and therefore failed sound timing/total duration. Explicit C-major metadata was absent. This is **not a lossless accepted conversion**.
- Irregular multi-staff duet, 3594×1836: eight pitched written events and three rests were retained, but two notes began at beat2 instead of3. The engine also changed voice labels/assignment, moved a tempo change from beat2 to1 and failed the second key signature, while the meter change and tie were retained. The engine logged key-export exceptions yet returned success and a MusicXML file. Matching pitch inventories and exit code0 do **not** establish rhythm or notation correctness. This deliberately complex, irregular-measure test is not a representative recognition-accuracy estimate.

Both tests require explicit correction. Engine confidence is unknown; no calibrated probability is supplied or invented. The current lightweight editor does not yet correct all multi-staff/key/tempo failures, so these results do not justify automatic trusted activation.

The preinstalled Ubuntu `tessdata_fast` English model lacks the legacy recognizer Audiveris needs. Evaluation switched only the private engine profile to the official [Tesseract tessdata](https://github.com/tesseract-ocr/tessdata/tree/ced78752cc61322fb554c280d13360b35b8684e4) English model: 23,466,654bytes, Git blob `f4744c201359d02ced6914c77f0de68ee9bbdd74`, SHA-256 `daa0c97d651c19fba3b25e81317cd697e9908c8208090c94c3905381c23fc047`, Apache-2.0. The pinned [Audiveris language guide](https://github.com/Audiveris/audiveris/blob/5.11.0/docs/_pages/guides/main/languages.md) explains its legacy-model requirement. No user-machine installation or license prompt was performed.

Direct engine MXL import was refused because ProxyMusic emits an external DOCTYPE. For evaluation only, a recorded normalization removed exactly its fixed `MusicXML 4.0.3 Partwise` external header from a separate copy; original MXL/XML bytes remained unchanged. The generic app importer still refuses DTDs/entities. A production bridge would need an explicit engine/version-scoped allowlist for exactly this header, no internal subset or entity resolution, raw-byte retention and a visible normalization diagnostic. It must not broadly enable DTD parsing.

`scripts/compare-score-content.py EXPECTED.json ACTUAL.json` compares already Rust-compiled fixture JSON and exits nonzero on compared-content differences. Part correspondence is explicitly positional, imported IDs are ignored, and voice labels remain strict in the structure metric. Sound timing is rounded to0.000001ms for representation stability, not a practice judgement window. Output shows full difference counts with bounded samples; a separate pitch-inventory match never hides tempo or rhythm errors. Six regression tests check spelling, exact rational equivalence, duplicate/rest retention, changed tempo and voice-label distinctions. This tool measures known original fixtures, not confidence or rights for unknown scores.
